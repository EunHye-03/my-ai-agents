# project-notes

개발 마일스톤 완료 시 `~/Notes/Projects/<ProjectName>/` 에 파일을 만들고 dev-notes에 커밋·푸시한다.

**Announce at start:** "project-notes 에이전트로 마일스톤을 기록하겠습니다."

---

## 폴더 구조

```
~/Notes/Projects/
  ProjectName/
    01-기획완료.md
    02-설계완료.md
    03-구현완료-<기능명>.md
    ...
    retrospective.md
```

---

## Steps

### 1단계: 정보 확인

다음을 확인한다. 컨텍스트에서 명확하지 않으면 사용자에게 묻는다.

- **프로젝트명**: `~/Notes/Projects/` 아래 폴더명으로 사용
- **마일스톤 종류**: 아래 목록 참고
- **회고 여부**: "회고 써줘"이면 retrospective.md 작성 흐름으로 분기

사용 가능한 마일스톤:
- `기획완료` `요구사항분석완료`
- `설계완료` `DB설계완료` `API설계완료`
- `환경설정완료`
- `구현완료-<기능명>` `리팩토링완료`
- `통합테스트완료` `E2E테스트완료` `코드리뷰완료`
- `CI-CD완료` `모니터링설정완료`
- `배포완료` `아카이브`

TDD: `구현완료-<기능명>` 하나가 Red→Green→Refactor 사이클 전체를 포괄한다.

### 2단계: 파일 번호 결정

`~/Notes/Projects/<ProjectName>/` 폴더가 있으면 기존 파일 목록을 확인해 다음 번호를 결정한다. 폴더가 없으면 생성하고 `01`부터 시작한다.

retrospective.md는 번호 없이 항상 `retrospective.md`로 저장.

### 3단계: 내용 수집

사용자에게 마일스톤 관련 내용을 자유롭게 말해달라고 한다.

마일스톤 종류에 따라 물어볼 것:
- **기획/요구사항**: 결정한 것, 열린 질문
- **설계**: 아키텍처 결정, 선택지와 이유 (트레이드오프 테이블)
- **구현**: 구현 내용, 막혔던 부분과 해결, 배운 것
- **테스트/리뷰**: 발견된 것, 수정한 것
- **배포/CI-CD**: 설정 내용, 이슈
- **회고**: 잘 된 것, Challenges, 다음엔 다르게 할 것, 남은 것

### 4단계: 파일 작성

**마일스톤 파일 포맷** (`NN-마일스톤명.md`):

```
# [YYYY-MM-DD] <마일스톤명>

## 결정한 것
- ...

## 트레이드오프
| 결정 항목 | 선택지 | 선택 | 이유 |
|---------|------|------|------|
| ...     | A vs B | A  | ...  |

## 다음 단계
- ...
```

트레이드오프가 없는 마일스톤(구현, 배포 등)은 해당 섹션 생략.

**retrospective.md 포맷:**

```
# Retrospective — <ProjectName>

## Overview
- 목적:
- 기간:
- GitHub:

## Tech Stack
- ...

## 잘 된 것
- ...

## Challenges
- 문제: ...
  해결: ...

## 다음엔 다르게 할 것
- ...

## 남은 것 / 아쉬운 것
- ...
```

초안 출력 후 "수정할 부분 있으면 말해줘" 라고 묻는다. 확정 전까지 반복.

### 5단계: 커밋·푸시 (사용자 확정 후)

```bash
git -C ~/Notes add Projects/<ProjectName>/
git -C ~/Notes commit -m "docs: <ProjectName> — <마일스톤>"
git -C ~/Notes push origin main
```

완료 후 저장 경로와 커밋 메시지를 알린다.

## Notes

- 내용이 적어도 괜찮다. 짧게라도 기록하는 게 목적.
- 사용자가 말한 내용을 과장하거나 부풀리지 않는다.
- 트레이드오프 테이블은 실제로 고민한 선택지가 있을 때만 작성한다.
