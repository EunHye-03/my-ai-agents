### 프로젝트 현황 상세

각 레포에서 수집:
- 현재 브랜치 (`git branch --show-current`)
- 최근 커밋 5개 (`git log --oneline -5`)
- 미커밋 변경 여부 (`git status --short`)
- `NOTES.md` 최근 날짜 항목

조건: `git log --since="30 days ago"`로 커밋이 있는 레포만 포함. 최대 10개 상한.

`~/src/repos/` 직접 glob 사용. 설정 파일 없이 해당 디렉토리 전체 스캔.

## Notion 우선순위 분류

Notion 할 일 항목에서 우선순위를 추출한다.

**우선순위 이모지 (EunHye의 현재 방식):**
- ‼️ = P0 (지금 반드시 해야 하는 것)
- ❗️ = P1 (오늘 안에)
- ❕ = P2 (여유 있으면)
- 이모지 없는 항목 = P1로 분류 (기본값)

**우선순위 정의:**
- P0: 오늘 반드시 해야 하는 것 (긴급+중요)
- P1: 오늘 안에 처리하는 것 (중요)
- P2: 여유 있으면 하는 것 (중요하지 않음)

**마감 정보:** 항목명에 `(MM/DD)`, `(YYYY-MM-DD)`, `~MM/DD` 형태로 마감일이 포함된 경우 추출.

## 현재 위험도 계산

모든 소스 수집 완료 후 위험도를 판정한다.

| 위험도 | 조건 |
|--------|------|
| 🔴 HIGH | P0 항목이 있고 마감이 오늘이거나 지난 경우; 또는 마감일 없는 P0 항목이 2개 이상 |
| 🟡 MED | P0 항목이 있고 마감이 내일 이후; 또는 P1 항목 중 마감이 오늘인 경우 |
| 🟢 LOW | P0 없고 긴급 마감 없음 |

## 공휴일 감지

날짜 확인 단계에서 오늘이 대한민국 공휴일인지 확인한다.

에이전트 자신의 지식(훈련 데이터)을 활용해 현재 연도의 대한민국 법정 공휴일 목록과 오늘 날짜를 비교한다. 공휴일이면 브리핑 상단에 표시한다.

## 브리핑 포맷

```
🗓️ YYYY-MM-DD (요일) 브리핑
[공휴일이면: 🎌 오늘은 [공휴일명]입니다]

🚨 현재 위험도: HIGH/MED/LOW
[위험도 판정 이유 한 줄]

🎯 지금 가장 중요한 한 가지
- [작업명] (예상 Xh | 마감까지 D일 / 오늘 마감)

✅ 오늘 할 일
**P0 — 지금 해야 함**
- [ ] 항목 1

**P1 — 오늘 안에**
- [ ] 항목 2

**P2 — 여유 있으면**
- [ ] 항목 3

👀 이번 주 놓치면 안 되는 것
- 항목명 (마감: MM/DD)

📅 일정
- HH:MM 일정명
- 내일: 일정명

📬 이메일 (미읽음 N건)
- 발신자: 제목 요약...

💬 Slack
- #채널명: 내용 요약...

🏫 학교 공지
- [CSE] 공지 제목...
- [SW교육원] 공지 제목...
- [국제처] 공지 제목...

💻 프로젝트 현황
- [레포명] branch: 브랜치명
  최근 커밋: 커밋 메시지 요약
  미커밋 변경: 있음/없음
  NOTES: 최근 항목 요약

🤖 AI 컨텍스트
- 메모리 파일 요약

💡 추천 행동
- 행동 1
- 행동 2
```

**포맷 규칙:**
- 위험도 섹션은 항상 날짜 바로 아래에 위치
- "지금 가장 중요한 한 가지"는 P0 항목 중 마감이 가장 가까운 것. P0가 없으면 P1 중 마감이 가장 가까운 것
- "이번 주 놓치면 안 되는 것"은 오늘~7일 이내 마감인 항목 (할 일 + 학교 공지의 마감 포함)
- "추천 행동"은 수집한 데이터 기반으로 2-3개 생성 (예: "미읽음 이메일 5건 — 빠른 확인 필요", "P0 마감 항목 오전 중 처리 권장")
- 진행률 바 없음

## 트리거 & 출력

| 트리거 | 출력 대상 |
|--------|-----------|
| 매일 아침 자동 (`/schedule` 등록) | Slack DM |
| "브리핑해줘" 수동 호출 | 터미널 출력 |

자동/수동 구분: 에이전트 호출 시 args에 `--slack` 포함되면 Slack 전송, 없으면 터미널 출력.

**자동 실행 주의:** `/schedule`이 원격 실행인 경우 로컬 파일·icalBuddy 접근 불가. 로컬 실행인 경우 Claude Code 세션 활성 상태 필요 (노트북 잠자기 시 스킵). 구현 시 실제 동작 방식 검증 후 결정.

## 에러 핸들링 원칙 (pre-mortem 반영)

각 소스는 개별적으로 격리 실행. 하나 실패해도 나머지는 계속 진행.

- 실패 시 해당 섹션에 `⚠️ [소스명] 데이터 수집 실패` 명시
- Notion 응답이 빈 배열이면 `⚠️ 할 일 0건 (Notion 직접 확인 권장)` 경고
- WebFetch HTTP 비정상 응답 시 "공지 없음" 대신 `⚠️ [사이트명] 접근 불가` 출력
- Slack 전송 후 응답 검증. 실패 시 터미널에 경고 출력
